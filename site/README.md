# Сайт — прототип (русская версия)

Статический сайт, собираемый генератором. CMS нет: контент правится в двух
файлах, результат — чистый HTML. Соответствует чеклисту `docs/site-build-playbook.md`.

## Структура

| Путь | Что |
|---|---|
| `content/ru.json` | интерфейсные тексты (заголовки, кнопки, разделы) |
| `content/works.csv` | работы: слаг, название, серия, год, техника, размер, цена |
| `src/style.css` | стили («классическая витрина») |
| `build.ps1` | генератор → `dist/` |
| `serve.ps1` | локальный сервер для просмотра |
| `dist/` | собранный сайт (генерируется, не править вручную) |

Изображения берутся из `../assets/works/` (`web/` — для страниц, `thumbs/` —
для сеток) и копируются в `dist/assets/img/`.

## Сборка и просмотр

```powershell
.\build.ps1                                   # собрать
.\build.ps1 -BaseUrl "https://имя-художницы.ru"  # с реальным доменом
.\serve.ps1                                   # http://127.0.0.1:8123/
```

## Публикация (GitHub Pages)

Прототип опубликован: <https://adastra-code.github.io/artist-site-prototype/>

Повторная публикация после правок:

```powershell
.\deploy-pages.ps1 -BaseUrl "https://adastra-code.github.io/artist-site-prototype"
```

Скрипт собирает `dist/` и кладёт его содержимое в ветку `gh-pages`
(плюс `.nojekyll`), из которой GitHub Pages отдаёт сайт. При переезде на
собственный домен — запустить с новым `-BaseUrl`, иначе `canonical`
и `sitemap.xml` будут указывать на старый адрес.

## Что где менять

- **Тексты, кнопки, разделы** → `content/ru.json`.
- **Добавить работу** → положить `web/<slug>.webp` и `thumbs/<slug>.webp`
  в `assets/works/` и добавить строку в `content/works.csv`
  (`series`: `painting` или `watercolour`; `available`: `yes`).
- **Цвета и типографика** → переменные в начале `src/style.css`.

## Дизайн: решения

- **Классическая витрина.** Светлый тёплый фон `#f7f5f1`, чёрный текст,
  крупная спокойная антиква в заголовках, много воздуха.
- **Masonry без обрезки.** Работы показываются в натуральных пропорциях —
  `object-fit: cover` не используется, потому что это картины, а не фото интерьеров.
- **Реальные размеры изображений.** `build.ps1` берёт `width`/`height` из
  `assets/works/inventory.csv` и пишет их в `<img>`, поэтому вёрстка не «прыгает»
  при загрузке.
- **Оба жанра равноправны.** «Живопись» и «Акварель» — разделы верхнего уровня.
- **Языки.** RU активен; EN/中文 показаны как «в подготовке». Каждый язык
  планируется отдельной HTML-папкой (`/ru/`, `/en/`, `/zh/`) с `hreflang`,
  а не подгрузкой текста скриптом — иначе не работает поиск.

## Заглушки — заменить до публикации

- **Телефон и соцсети не указаны** — в футере их просто нет. Если появятся,
  достаточно добавить `phone` и/или `instagram` в блок `site` файла
  `content/ru.json`: разметка подхватит их сама.
- Тексты «О художнике» и список выставок — помечены как `ЗАГЛУШКА`.
- Названия работ в `content/works.csv` — рабочие, из описаний в каталоге фото.
- Год, размер и цена работ — пустые (не выдумывались).
- `-BaseUrl`: по умолчанию `https://example.ru`, из-за чего `canonical`,
  `og:url` и `sitemap.xml` указывают на пример. Заменить на реальный домен.
- Форма подписки (`action="#"`) никуда не отправляет — нужен сервис рассылки.
- `hreflang` появится вместе с английской и китайской версиями.
